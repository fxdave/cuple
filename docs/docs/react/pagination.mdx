# Pagination

```tsx file=../../../examples/react/src/App.tsx#notes
```

In this example:

 - The third argument returns the next page's arguments from the last page, or `null` when there are no more.
 - `pages` holds the loaded pages, success only. A failed page throws to the nearest `<Boundary>`.
 - `loadMore` keeps the loaded pages on screen, and `isPending` is true until the next page lands.
 - While `isPending` is true, placeholder rows show where the next page will land.
 - Every page is an ordinary cached call. Refreshing `client.getNotes` refetches every loaded page, and when a deleted note shifts the pages, the next arguments follow.

:::note[Why it works this way]

- **Pages are ordinary cached calls.** Refreshing, sharing and errors work the same as for any read; there's no separate infinite-query cache with its own rules.
- **The next arguments come from the last page.** Cursor, offset or page number: your function derives them, so the hook doesn't need to know your API's paging style.
- **Success only in `pages`.** A failed page goes to the boundary, so the list never mixes data and errors you'd need to filter.

:::
