# Streams

For endpoints made with [getSSE](../server/sse).

```tsx file=../../../examples/react/src/App.tsx#activity
```

In this example:

 - The callback runs for every event. Events are not stored: you decide what to keep, and what to refresh.
 - `store.refresh(...)` refetches what's on screen when someone else changed it.
 - The connection is closed when the component unmounts, and opened again when the arguments change.
 - A rejected connection (e.g. `401`) throws to the nearest `<Boundary>`, like a failed read.
 - A network failure is kept as `error`, with `isStreaming: false`: streams drop, and the page should stay. `reconnect()` tries again.
 - `StreamEvent` gives you the event type from the server.

:::note[Why it works this way]

- **Events aren't kept.** A stream is a series of changes, not a value; kept in memory, it grows forever. Usually an event means "something changed", and refreshing the reads it affects keeps one source of truth for what's on screen.
- **A rejected connection throws, a dropped one doesn't.** A `401` won't fix itself, so it's an error for the boundary. A long-lived connection dropping is normal (a laptop going to sleep), so it's state the component shows while you reconnect.

:::
