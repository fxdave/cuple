# Combining reads

`combine` turns several reads into one value. It's a plain async function: `ctx.get` reads through the cache, and what you return is what `useGet` gives back.

```ts
export const loadSomething = combine(async (ctx, args: Args) => {
  const a = await ctx.get(client.someRoute, ...);
  return /* anything built from them */;
});

const value = useGet(loadSomething, args);
```

The examples below run as one app: `cd examples/docs && npm run dev:combine`. Its routes:

## A read that needs another's result

The customer's id is in the order, so the second `ctx.get` waits for the first. A deleted customer is a normal outcome here, so it's listed with `resolveAlso` and comes back as a value. Anything unlisted fails the whole read and goes to the `<Boundary>`:

## A POST that only reads

Reads are GET only. A search sent as a POST is still a read, so wrap it: it's cached by its args like any read. `fetchCuple` sends the request directly, without the cache:

## Load more

The combined read loads the first `count` pages. The component holds `count`, and raises it in a transition, so the loaded notes stay on screen while the next page loads. See [Pagination](./pagination) for page numbers and how refresh works:

## The rules

 - **Create combined reads at module level.** A combined read's identity is its cache identity; one created during render would never hit the cache.
 - **Args must be JSON** (numbers, strings, plain objects and arrays): they're the cache key.
 - **It owns what it fetches.** The calls made through `ctx.get` are kept as long as the combined read is, whatever their own cache settings. So "load more" fetches one page, never all of them again.
 - **Refreshing a route re-runs every combined read that read it.** `refresh: [client.getOrder]` updates `loadOrderWithCustomer` too.
 - **`ctx.get` shares requests** with every other reader: if the list already loaded a customer, the order page doesn't fetch it again.

:::note[Why it works this way]

Combining reads is a plain async function, so there's nothing new to learn.

During the design, a combined read was going to keep state of its own, such as how many pages were loaded. But a combined read lives in the cache, so whenever the cache dropped it, that state would be lost. So state lives in React (`useState`, the URL) and is passed in as arguments. The cache should only make things faster, never change what you see.

:::
