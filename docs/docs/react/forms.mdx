# Forms

A contacts CRUD with [react-hook-form](https://react-hook-form.com/). The server validates; the form shows what it says.

## The form

```tsx file=../../../examples/react/src/contacts.tsx#contact-form
```

In this example:

 - `form.handleSubmit(save.run)`: `run` resolves when the save and its refresh are done, and never rejects, so react-hook-form's `isSubmitting` covers the whole save.
 - `thenResolveAlso(["invalid-body", "transport-error"])` keeps what the form can explain as values: the server's validation errors go on the fields, a dropped connection on the form, and the user's input stays.
 - Anything else (a 500, a bug) is unhandled; `errors.onError: "notify"` shows it without replacing the form.
 - `refresh: { success: [...] }`: only a successful save changed anything worth refetching.

 - NOTE: To clear the form after a save, call `form.reset()` after `run` resolves, not inside the action. `reset` also clears `isSubmitting`, which would end the submission before the refresh.

## Server errors on the fields

```tsx file=../../../examples/react/src/contacts.tsx#server-issues
```

An issue's path is the field's name, nested ones included: `["address", "zip"]` becomes `address.zip`. Rules only the server can check (an email already in use) come back the same way, so the form needs no special case for them.

## Create and edit

```tsx file=../../../examples/react/src/contacts.tsx#new-and-edit
```

 - The edit form loads its contact before it mounts, so react-hook-form starts with the real values. There's no `reset` after load, and no flash of an empty form.
 - Each contact's form has its own `key`, so opening another contact starts a fresh form.

## Delete

```tsx file=../../../examples/react/src/contacts.tsx#contact-row
```

Deleting the contact whose form is open closes the form inside the action, so the deleted contact is never refetched.

:::note[Why it works this way]

- **The server validates.** Rules like "email already in use" can only be checked there, and a client-side copy of the others drifts. Every rule comes back as an `invalid-body` with a path, so the form has one way to show all of them.
- **No form adapter.** `run` resolves when the save and its refresh are done, which is exactly what `handleSubmit` waits for. react-hook-form's `isSubmitting` covers the whole save without glue code.

:::
