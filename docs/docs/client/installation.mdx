# Installation

```bash
npm i @cuple/client
```

NOTE: **@cuple/client** and **@cuple/server** versions have to match

## Create a client

We need to tell Cuple about the server's location.
Since the client has no way to get the specified path information without a code generator,
currently every request goes to one path (usually `/rpc`) with the desired HTTP method.

```ts
// cuple.ts
import { createClient } from "@cuple/client";
import type { routes } from "../backend/src/app";

export const client = createClient<typeof routes>({
  path: "http://localhost:8080/rpc",
});
```

## Use it like a fetch

```ts
import { fetchCuple } from "@cuple/client";

async function getPost(id: number) {
  // Resolves with success; any other result throws.
  const { post } = await fetchCuple(client.getPost.get, { params: { id } });
  return post;
}

async function findPost(id: number) {
  // A failure you handle is listed, and typed.
  const res = await fetchCuple(client.getPost.get, { params: { id } }).thenResolveAlso([
    "not-found-error",
  ]);
  return res.result === "not-found-error" ? null : res.post;
}
```

See [Handling results](./handling_results).

:::note[Why it works this way]

- **No code generator.** A generated client is only as fresh as its last generation; forget that step, and the client compiles against an old API. Here the types come from `typeof routes`, so a server change is a client type error as soon as you save.
- **One RPC path.** Without generated code, the client can't know each route's URL, so requests name the route on one path (`/rpc`). Routes with `.path()` are still plain REST for other clients.

:::
