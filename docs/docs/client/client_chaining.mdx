# Client chaining

`client.with({ ... })` returns a client that adds the same data to every request, like an authorization header.

```ts
const client = createClient<typeof routes>({
  path: "http://localhost:8080/rpc",
});

const authedClient = client.with({
  middleware: () => ({
    headers: { authorization: localStorage.getItem("token") || "nothing" },
  }),
});

// GOOD:
await fetchCuple(authedClient.getProfile.get);

// ALSO GOOD:
await fetchCuple(client.getProfile.get, {
  headers: { authorization: localStorage.getItem("token") || "nothing" },
});

// A route that requires the header, called without it, is a type error:
await fetchCuple(client.getProfile.get); // TYPE ERROR
```

## Options

| Option | Runs | For |
| ------ | ---- | --- |
| `middleware` | Before every request; awaited, so it can refresh a token. | Data every request needs: headers, a tenant id. |
| `key` | When a cache needs it (a string, or a synchronous getter). | Telling caches whose data a response is. See [Switching accounts](../react/store#switching-accounts). |
| `finalware` | After every response, before it's handed back. | Cross-cutting reactions: redirect on an expired session, report failures. Throwing turns a result into an exception. |

 - NOTE: `key` is what the response depends on (who the user is), not the injected bytes (the token). A refreshed token is the same user.
 - NOTE: `finalware` can replace the response, but the types don't follow it. Observe or throw; don't reshape.

:::note[Why it works this way]

- **Required headers are part of the type.** A forgotten auth header is otherwise a `401` found in production. When the route's schema requires it, a call without it doesn't compile.
- **`middleware` runs per request.** Tokens expire. Reading the token when the request is sent means a long-lived client never sends a stale one.
- **`key` is separate from `middleware`.** A cache can't see what middleware injects, and the token changes while the user doesn't. Naming the identity keeps cached data apart per account, without discarding it on every token refresh.

:::
