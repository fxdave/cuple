# MCP

With `@cuple/mcp`, AI agents can call your routes as [MCP](https://modelcontextprotocol.io) tools: in Claude, ChatGPT, Cursor or any other MCP client.

```bash
npm i @cuple/mcp
```

## Example

An MCP endpoint is a route of your own, with its own auth link:

```ts
import { createMcpEndpoint } from "@cuple/mcp";

export const mcp = createMcpEndpoint(builder.path("/mcp").chain(mcpAuthLink), {
  tools: (b) => ({
    listMyPosts: b
      .meta({ description: "Lists the signed-in user's posts, newest first." })
      .querySchema(z.object({ limit: z.number().max(50).optional() }))
      .get(async ({ data }) => success({ posts: await posts.of(data.user, data.query.limit) })),
  }),
});
```

```bash
claude mcp add --transport http my-api https://api.example.com/mcp --header "Authorization: Bearer …"
```

In this example:

 - The tools are routes built on the endpoint's builder, so they run after `mcpAuthLink` and see what it gave (`data.user`). The agent never sends credentials to them.
 - A tool's name is its key, and nested groups join with underscores (`posts_list`), since Claude's and OpenAI's APIs reject dots.
 - A tool's description is the route's `.meta({ description })`. Write it for the agent: what the route is for and when to call it.
 - A tool's inputs are the route's `params`, `query`, `body` and `headers` schemas, side by side: `{ id, title }`, which agents fill more reliably than nested parts. A route whose parts share a field name keeps the parts; `flatten: false` keeps them for every tool.
 - GET routes are marked read-only and DELETE routes destructive, so clients that ask before each change (ChatGPT does) let reads through. A POST route that only reads says so with `.meta({ readOnly: true })`; `.meta({ destructive: true })` marks one that deletes.
 - The response comes back as JSON, both as text and as `structuredContent`. If it's not `success`, the tool call is marked as an error.
 - Only JSON endpoints can be tools. SSE, raw (`getRaw`, …) and `rawBody()` endpoints are a type error, and an error at startup.

 - NOTE: A route without a description, or with a schema JSON Schema can't express (`z.date()`), works, with a warning at startup.
 - TIP: Clients cap how much of a result they read (Claude Code: about 25,000 tokens). Give list routes a limit and an offset, and say so in their descriptions.

## Borrowing routes

Routes you made for your app can be tools too. Pick exactly the ones to offer: an agent reaches nothing else through MCP. They take their own credentials, so `inject` makes them from what the endpoint's chain gave:

```ts
export const mcp = createMcpEndpoint(builder.path("/mcp").chain(mcpAuthLink), {
  routes: {
    pick: { getPost: routes.posts.getPost, createPost: routes.posts.create },
    inject: async ({ data }) => ({
      headers: { authorization: `Bearer ${await appTokenFor(data.user)}` },
    }),
  },
});
```

 - `inject` runs once per MCP request. The keys it returns are taken out of the tools, so the agent neither sees nor overrides them, and go with every call.
 - What it returns is up to your app: a token your auth link accepts, a cookie, a tenant id in the query. The MCP credential itself never needs to work on your app's routes.
 - `toolListMiddleware` shapes the tool list per caller: drop what they can't use, or say how to get it. The agent can call only what it returns.

```ts
toolListMiddleware: async ({ data, tools }) =>
  data.plan === "pro"
    ? tools
    : tools.map((tool) =>
        tool.name.startsWith("reports_")
          ? { ...tool, description: `${tool.description} Needs the Pro plan: upgrade under Settings.` }
          : tool,
      ),
```

## Signing in

When the endpoint's chain answers 401, the endpoint sends it with `WWW-Authenticate: Bearer`, which tells MCP clients to ask the user for credentials again. For OAuth, clients then look for your [protected resource metadata](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization) at `/.well-known/oauth-protected-resource/mcp`; `wwwAuthenticate: 'Bearer resource_metadata="…"'` points them elsewhere.

 - NOTE: The endpoint is stateless [Streamable HTTP](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports#streamable-http): every request is answered as plain JSON, so proxies that buffer responses don't get in the way, and GET and DELETE are 405.

## Over stdio

A local agent can start an MCP server of its own. That's a separate process, so it calls your API through a client:

```ts
// mcp.ts
import { createClient } from "@cuple/client";
import { serveMcp } from "@cuple/mcp";
import { routes } from "./src/routes";

serveMcp(routes, createClient<typeof routes>({ path: "http://localhost:8080/rpc" }).with({
  middleware: () => ({ headers: { authorization: `Bearer ${process.env.API_TOKEN}` } }),
}));
```

```bash
claude mcp add my-api -- npx tsx mcp.ts
```

 - What the client's middleware injects is hidden from the tools, like `inject` above. Without it, a route that needs `authorization` says so in its tool.
 - NOTE: `serveMcp` talks to the agent over stdout, so nothing else may write to it: not `mcp.ts`, nor the modules it imports. Log to stderr (`console.error`).
 - `createMcpServer(routes, client)` returns the server without connecting it, for any transport from `@modelcontextprotocol/sdk`.

:::note[Why it works this way]

MCP is here so AI agents can easily call Cuple endpoints. They're good with HTTP but don't know Cuple's `/rpc` protocol, and the tools do that part for them. It's early and not well tested yet.

Tools are your routes, run in-process, so an agent gets the same validation, middlewares and auth as your app, and can reach nothing you didn't hand it. MCP's auth is separate from your app's: an agent with an MCP token is not a browser session, so the endpoint decides what it may call and `inject` decides what those calls carry.

:::
